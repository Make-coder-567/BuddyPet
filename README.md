# Buddy 桌面宠物

WorkBuddy 的桌面常驻小助手。形象取自 WorkBuddy 成长中心的「盲盒 Buddy」——猫耳机器人 + 橙色工装。

- 常驻桌面、始终置顶、透明无边框，鼠标可穿透到桌面
- **左键单击** → 唤起 / 打开 WorkBuddy 主程序
- **右键单击** → 上下文菜单（设置 / 互动效果 / 置顶 / 锁定 / 退出）
- **按住拖动** → 换位置；松手自动记住
- **双击** → 来一局石头剪刀布
- **Ctrl+Alt+B** → 全局唤出 / 隐藏（在别的程序里也生效）
- **拖入文件** → 按类型给不同反应（图片冒心、音频跳舞、代码闪光…）
- **检测到音乐/音频** → 自己摇两下
- **一段时间没操作电脑** → 自己松开边缘、在屏幕里自由溜达；你一回来就小跑归位
- 待机呼吸、随机眨眼、定时小互动；10 个可切换的互动特效

## 快速开始

双击下面任意一个都可以，会自动找到 `pythonw.exe` 后台启动：

| 文件 | 特点 |
| --- | --- |
| `启动桌面宠物.vbs` | 推荐。全程无窗口，双击即启动 |
| `启动桌面宠物.bat` | 兼容性最好，会闪一下黑色命令行窗口 |

命令行启动：`python main.py`（可看报错信息）。

首次运行依赖：

```bat
pip install -r requirements.txt
```

> `pillow` 只在重新生成眨眼帧（`tools/make_frames.py`）时需要，日常运行只依赖 PyQt5。

不想每次都手动点？右键宠物 → **设置…** → 打开 **开机自动启动**（写入注册表 `HKCU\...\Run`，可随时关闭）。

### 视线跟随

鼠标靠近时，眼睛会在面罩里转向光标，头部跟着偏一点；走远或移出屏幕就回正。

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 触发距离 | 460 px | 以**眼睛中心**为圆心；超出即回正 |
| 死区 | 40 px | 太近不产生偏移，避免停在眼前时抖动 |
| 方向映射 | smoothstep | 距离在 40→460 px 之间归一到 0..1，再由单位向量给出方向 |
| 平滑方式 | 指数插值 `k = 1 - e^(-9·dt)` | 与帧率无关；另加 4.2/s 的单帧位移上限防跳变 |
| 眼睛位移 | 水平 0.026×身高、垂直 0.020×身高 | 例：200 px 高时约 ±5.2 / ±4.0 px |
| 眼睛压缩 | `1 - 0.18×|nx|` | 侧看时轻微压扁，模拟弧面面罩 |
| 头部联动 | 旋转 `3.0° × nx`、横移 `0.012×身高` | 眼睛先动、头随后，幅度约为眼睛的 1/2 |
| 眨眼 | 复用同一双眼睛纵向压缩 | 眨眼时视线不会跳回中心 |

回正条件：距离 > 460 px、隐藏、或设置里关掉「视线跟随鼠标」。**贴边（左/右/上/下）时视线同样生效**——左/右贴边走专用抓边立绘，其眼睛也已拆分出独立图层，会跟随光标；上/下贴边改用分层眼睛绘制，方向与鼠标一致。

**性能**：每帧只做一次 `QCursor.pos()` + 两次向量运算，眼睛贴图按尺寸缓存；实测 60 FPS 下进程占用约 11% 单核（0.55% 系统）、内存 65 MB。

### 贴边抓握（四条边）

把宠物拖到屏幕**左 / 右 / 上 / 下**任意一边，松手时离该边 28px 以内就会吸附上去并抓住：

| 边缘 | 姿态 | 抓握点 |
| --- | --- | --- |
| 左 / 右 | **双手扣边**：专用抓边立绘，双手压在边框上、指尖越过边线，身体前倾挂着，单脚离地；右边缘用镜像 | 双手 |
| 上 | **倒挂**：整体翻转，头朝下悬在顶边，幅度 2.6° 轻摆 | 双脚 |
| 下 | **停靠**：屈膝坐住（纵向压缩 5.5%），轻微起伏 | 脚底 |

判定与表现：

1. 判定用**窗口外框**到屏幕可用区域（已排除任务栏）的距离，四边同一套阈值 `EDGE_SNAP = 28px`；
2. 四边同时满足时取**距离最小**的一条边（角落优先吸附更近的那条）；
3. 左右吸附时会把抓边立绘居中到窗口，画面里手正好压在屏幕边线上，指尖越过边线被屏幕裁掉，形成"扣住边框"的遮挡关系；上边缘留 3px 让脚爪压边；
4. 抓住瞬间先下沉 7px 再回弹，接触点按边方向扬起细灰；
5. 待机时每 10–20 秒「再抓一把」，轻微挪动 + 扬尘。

**什么时候松手**：拖走（拖动即松手）、右键 →「松开边缘」、右键 →「回到右下角」、设置里关掉「贴边依附」、或播放「旋转登场」这类大幅旋转特效（会先松手再转）。重启后按保存的位置自动恢复抓握状态。

右键菜单 → **切换 Buddy…** 打开设置里的「Buddy 图鉴」分组，可以浏览所有可用形象与皮肤、在预览里看到实时眨眼，并**立即**把选中的皮肤换上：

| 操作 | 效果 |
| --- | --- |

| 点「应用此皮肤」 | 立刻换肤并落盘，**不受**面板「保存 / 取消」管辖 |
| 点「放弃更改」 | 只把面板内选中态还原成当前生效组合，不碰配置 |

- **立即提交语义**：换肤落地后，即使你接着点「取消」或「恢复默认（设置面板）」，已生效的皮肤也不会被偷偷改回去（`config.GALLERY_OWNED_FIELDS` 不受面板回滚影响）。

- **换肤淡入**：切换后 180ms 淡入，新旧形象之间平滑过渡。
- **皮肤包规范**见 `docs/skin_manifest.md`；自定义皮肤只需按规范放到 `assets/skins/<buddy>/<skin>/` 即可被自动识别。

## 全局快捷键

在**任何程序**前台时按 <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>B</kbd> 都能唤出 / 隐藏宠物，比去点托盘图标快得多。

| 项 | 说明 |
| --- | --- |
| 实现 | `RegisterHotKey(NULL, id, Ctrl|Alt|MOD_NOREPEAT, VK_B)` + `QAbstractNativeEventFilter` 捕获 `WM_HOTKEY`（`windows_generic_MSG` 与 `windows_dispatcher_MSG` 两种事件类型都接） |
| 防连发 | `MOD_NOREPEAT`，长按不会让宠物疯狂闪烁 |
| 隐藏时 | 托盘气泡提示「点托盘图标或按 Ctrl+Alt+B 可以叫我回来」 |
| 唤出时 | 气泡说一句（台词池 `hotkey_show`） |
| 注册失败 | 典型是别人已经占了这组合键（Win32 错误 1409）：只弹一条托盘提示 + 一句气泡，**其余功能完全不受影响** |
| 关闭 | 设置 → 交互 → 全局快捷键，或右键菜单 / 托盘菜单的勾选项；立即注销 |
| 其它平台 | 非 Windows 一律返回「注册失败」但不抛异常，功能静默降级 |

## 拖放文件

把文件（或文件夹、网页链接）**拖到宠物身上**松手就行。

**拖入过程中**：窗口遮罩临时铺满整窗，画一圈橙色虚线圆角框（内填 6% 橙），宠物轻微呼吸式放大并带光晕，同时响一声轻响、说一句「放下来给我看看～」。移出去就恢复原本的轮廓遮罩。

**松手之后**按类型给不同反应（**只读取名字和大小，绝不复制、移动或打开文件**）：

| 类型 | 扩展名 | 特效 | 台词池 |
| --- | --- | --- | --- |
| 图片 | png jpg jpeg gif webp bmp svg ico | 爱心暴击 | `drop_image` |
| 音频 | mp3 wav flac m4a ogg aac wma | 摇摆舞步 | `drop_audio` |
| 代码 | py js ts tsx jsx java c cpp h cs go rs json yaml yml html css sh bat | 星光闪烁 | `drop_code` |
| 文档 | doc docx pdf txt md ppt pptx xls xlsx csv | 星光闪烁 | `drop_doc` |
| 压缩包 | zip rar 7z tar gz | 盲盒开箱 | `drop_archive` |
| 其它 / 无扩展名 | — | 盲盒开箱 | `drop_other` |
| 文件夹 | — | 盲盒开箱 | `drop_folder` |
| 网页链接 | — | 星光闪烁 | `drop_url` |
| 多个文件 | — | 彩带礼花 | `drop_multi` |

气泡先说具体信息（`收到「报告.pdf」 1.2 MB` / `收到 3 个文件！`），1.9 秒后再补一句分类台词。统计写进配置：`drop_count` 累加、`last_drop_path` 记录最后一个路径。

## 音乐感知

宠物会「听见」你在放东西：系统一出声它就摇两下，安静下来就停。

- **零依赖**：只用 `ctypes` 调 Core Audio 的 `IAudioMeterInformation::GetPeakValue` 读默认输出设备的峰值；再用 `EnumWindows` + 进程名/标题识别是不是音乐播放器（网易云、QQ音乐、酷狗、酷我、Spotify、foobar2000、Apple Music…）。
- **判定**：起播阈值 `0.004`、停播阈值 `0.0015`（滞回），并且**连续 2 次同向**才真正切换，避免一次「叮」就让宠物跳起来。
- **区分**：命中音乐播放器 → `music`（跳摇摆舞）；只是有声音（视频、会议）→ `audio`（轻轻眨个眼），不喧宾夺主。
- **降级**：没有音频设备或非 Windows 时 `peak` 返回 `None`，改用「有没有音乐播放器在跑」判断，内部标记 `degraded`。
- **不打扰**：首次采样在启动 1500ms 后，**只建档不发信号**（一开机不会自己跳舞）；之后每 8 秒轮询一次，全部调用都在 `try/except` 里。
- **可关**：设置 → 交互 → 音乐感知，或右键/托盘菜单。关掉后立即停止轮询并把律动收回去。

命令行排查：`music:on` / `music:off` 强制开关，`music:status` 把一次探测的原始结果（`playing / kind / title / peak / music_app / degraded`）写到 `%APPDATA%\WorkBuddyPet\music_status.json`。

## 空闲自动漫游

没人碰电脑一会儿，Buddy 会松开边缘下地溜达；你一动键鼠，它就小跑回原来的位置坐好。

### 怎么判断「人不在」

| 项 | 值 / 行为 |
| --- | --- |
| 空闲来源 | Windows `GetLastInputInfo` —— 读的是**全系统**最后一次键鼠输入，不是本进程的输入 |
| 轮询 | 500 ms 一次；单次调用约 0.01 ms，几乎零开销 |
| 进入空闲 | 连续 2 次采样都超过阈值（默认 3 分钟）才触发，避免采样相位抖动 |
| 退出空闲 | 一次采样低于阈值就立刻结束，唤醒延迟 ≤ 500 ms |
| 首次采样 | 只建档不发信号 —— 刚开机不会自己跑起来；若建档时人已离开，下一 tick 仍会正常触发 |
| 非 Windows / API 失败 | 退化为「光标是否移动 + 应用内活动」近似判断，状态里标记 `degraded=true` |
| 离屏 / 无 GUI | 直接判定不可用，返回 `idle_sec=null`，**绝不误报空闲**（自动化测试靠 `force()` 驱动） |

`GetLastInputInfo` 的 `dwTime` 用无符号 32 位减法处理 `GetTickCount` 的 49.7 天回绕，不需要 `GetTickCount64`。

### 它会做什么

状态机：`off → walk ⇄ pause → return → off`。

| 状态 | 行为 |
| --- | --- |
| `walk` | 在**当前屏幕可用区域**内选目标（排除任务栏）：离当前点 120 px ~ 屏宽 75%，六成落在下半「地面带」，四成允许满屏跑；速度有上限、靠近目标减速，绝不瞬移。步态是上下起伏 + 左右摆角 + 起步轻微侧身 |
| `pause` | 到达后停 1.2~4.0 s；限频 10~22 s 且引擎空闲时，随机说一句或放一个小特效（眨眼 / 爱心 / 星光 / 弹跳 / 咖啡 / 打盹） |
| `return` | 说一句「你回来啦」，以同样的步态跑回原位，恢复原来的贴边抓握状态 |

边界与不打扰：

1. **位置语义**：漫游全程**不写 `cfg.pos`、不落盘**。归位后仍在老地方；意外退出 / 崩溃后重启也不会停在半路。关掉「回来时归位」时，结束才把落点记为新家。
2. **打断**：直接点宠物会**就地停住**（不瞬移 —— 否则 `mousePressEvent` 里算的拖拽偏移会错位），并把落点记成新位置；随后检测器补发的 `idle_ended` 在 `off` 状态下是幂等的。
3. **让路**：锁定位置、宠物隐藏、设置/游戏/右键菜单打开时不启动；拖拽中不移动窗口；待机随机互动、音乐律动照常叠加，互不打架。
4. 漫游期间固定使用「带抬升余量」的轮廓遮罩，避免步态反复穿过 `±3px` 阈值导致每帧 `setMask` 来回切换。

### 设置项

设置 → 交互，或右键 / 托盘菜单 → 互动效果 → **空闲自动漫游**。

| 选项 | 默认 | 范围 / 说明 |
| --- | --- | --- |
| 空闲自动漫游 | 开 | 总开关；关掉时立即归位 |
| 触发空闲时长 | 3 分钟 | 1~30 分钟 |
| 漫游速度 | 78 px/s | 30~180；再乘活泼程度 `0.65 + 0.35 × liveliness` |
| 回来时归位 | 开 | 关掉则就地停住，并把落点记为新位置 |
| 漫游时随机互动 | 开 | 关掉就只安静走路 |

### 不用等 3 分钟就能预览

单实例命令通道支持强制注入（`idle:on` 保持 60 秒，期间不被自动轮询纠正）：

```bat
python -c "from PyQt5.QtWidgets import QApplication;from PyQt5.QtNetwork import QLocalSocket;a=QApplication([]);s=QLocalSocket();s.connectToServer('WorkBuddyDesktopPet-1');s.write(b'idle:on');s.flush();s.waitForBytesWritten(500)"
```

把 `idle:on` 换成 `idle:off` 立刻收场、`roam:toggle` 切总开关、`idle:status` 把检测明细与漫游状态写到 `%APPDATA%\WorkBuddyPet\idle_status.json`（含 `idle_sec / threshold_sec / source / degraded / forced / roam.state / roam.pos / roam.home`）。

| 操作 | 效果 |
| --- | --- |
| 点「石头 / 剪刀 / 布」 | 按钮锁定 →「石头… 剪刀… 布！」每 220ms 一句 → 亮出双方出拳 |
| `1` / `2` / `3` | 等价于点三个按钮（别名：石头 / 剪刀 / 布） |
| `Enter` | 再来一局 |
| `Esc` | 退出 |

胜负：石头胜剪刀、剪刀胜布、布胜石头，相同为平。每局结束写 `rps_wins / rps_losses / rps_draws` 并落盘，卡片底部实时显示「战绩 X 胜 · Y 平 · Z 负」；同时通知主窗口放特效：赢撒彩带、输起跳、平眨眼。

## 实现要点

**透明 + 可点击**：窗口用 `WA_TranslucentBackground` + `FramelessWindowHint | Tool | WindowStaysOnTopHint`；再用 `setMask()` 把窗口形状裁成宠物轮廓，这样桌面上大片透明区不会吃掉鼠标。宠物起跳时自动切换到带「抬升余量」的遮罩，落地再切回，避免头部被裁。

**粒子单独一层**：粒子要飘到轮廓之外，但遮罩会把窗口内超出轮廓的部分裁掉。所以粒子画在第二个窗口里，该窗口设为 `WindowTransparentForInput` + `WS_EX_TRANSPARENT`，不接收鼠标、不抢焦点；没有粒子时自动隐藏，省资源。

**眨眼**：立绘的眼睛是画在面罩上的，无法直接动。脚本先用两侧像素对眼睛区域做水平插值修补出「无眼面罩」，再把眼睛按不同纵向比例压扁贴回，得到 6 帧眨眼序列；合成时用一层青色软遮罩限定范围，避免出现方框接缝。

**眼睛拆分**：原立绘的眼睛画在面罩上动不了，所以 `tools/make_eye_assets.py` 先把眼睛区域按水平渐变修补成「无眼面罩」（`buddy_base.png`），再把青色像素连同抗锯齿边缘抠成 `eye_l.png` / `eye_r.png` 并记录坐标。运行时画「底板 + 按视线偏移的眼睛」，眨眼则改为纵向压扁同一双眼睛，因此视线与眨眼可以同时发生。

**抓边立绘**：原立绘的手臂垂在身侧，抬不到屏幕边上，所以另生成了一张「双手扣住竖直边框」的同角色姿态（`assets/frames/buddy_grip.png`，右边缘用镜像）。`tools/make_grip_asset.py` 负责把生成图处理成素材：取最大连通域抠掉棋盘格背景、填平内部空洞保住白色太空服、清掉模型自带的辅助竖线、按内容裁边。为了让抓边姿态也能做视线跟随，再用 `tools/make_grip_eye_assets.py` 从抓边图里基于面罩亮度对比 + 连通块筛选自动拆出眼睛，得到 `buddy_grip_base.png` + `grip_eye_l.png` + `grip_eye_r.png` + `eyes_grip.json`（`eyes_grip.json` 的字段格式与 `eyes.json` 完全一致）。运行时抓边姿态优先走「去眼底板 + 按视线偏移的眼睛」，缺这套素材时退回整张静态抓边图。

**贴边的遮罩**：窗口形状是 `setMask` 裁出来的，宠物一旦倾斜或翻转，身体就会越出静止轮廓被裁掉。所以进入贴边状态时会用「与绘制完全相同的变换，逐角度渲染同一张立绘」重建一张覆盖摆动范围的遮罩（左右取 -24°~21°、上边缘取 ±10° 含翻转、下边缘只做压缩），并向上/向下并集 0.34h 覆盖跳跃；退出贴边再切回普通轮廓。绘制与遮罩共用 `_apply_pet_transform()`，避免两处变换写法不一致导致边缘被切。

**动画**：60 FPS 定时器驱动，特效各自维护姿态曲线（缩放 / 位移 / 旋转 / 透明度 / 眼睛帧），逐帧叠加到待机呼吸与悬停放大之上，互不打架。

**拖入时换成整窗遮罩**：平时窗口用 `setMask` 裁成宠物轮廓，虚线提示框画在轮廓外就会被裁掉。所以进入拖入态时把遮罩临时换成整个窗口矩形（`QRegion(self.rect())`），`paintEvent` 先画虚线框、再画宠物；松手或移出时用 `_apply_mask()` 恢复（贴边时恢复的是贴边轮廓）。`_tick` 里切换遮罩的判断加了 `if not self._drag_over` 守卫，否则待机呼吸会把遮罩每帧改回轮廓。

**音乐律动不改特效**：不新增特效，只在 `_tick` 末尾叠加一层「权重缓动」的微小摆动 —— `_music_groove` 以 `k = min(1, dt×2.5)` 缓动到 0/1，再乘活泼程度给出 ±1.8° 旋转与 ±1.0px 位移。关掉音乐时权重自然衰减到 0，姿态不会突然定格；拖动中不律动（免得两个位移打架）。

**空闲漫游不改架构**：`IdleWatcher` 只回答「人有没有在操作」，`RoamController` 只回答「现在往哪走」，两者靠 `idle_started / idle_ended` 两个信号连接。`PetWindow._tick` 末尾调一次 `roam.step(dt)`：位置由控制器直接 `move()`（复用 `moveEvent → _sync_overlay`，粒子层自动跟随），姿态以 `bob / rot / sx / sy` 叠加到当帧 `Pose` 上，不新增特效、不改 `EffectEngine`。控制器从不写 `cfg.pos`，只有结束（且不归位）时才落盘；`quit()` 先 `finish(immediate=True)` 再取位置，避免把半路坐标存成下次启动的位置。

**双击与单击**：`mouseReleaseEvent` 不再直接执行单击，而是启动一个 `min(260, doubleClickInterval())` 的单次定时器；`mouseDoubleClickEvent` 先 `stop()` 它并发 `rps_requested`，同时置 `_ignore_click` 让双击的第二下松手不再排一次单击。

**单实例**：`QLocalServer` 占名，重复启动时向已有实例发命令并退出；同一个通道也用于自动化测试（`effect:box` / `settings` / `rps` / `music:on|off|status` / `hotkey:toggle` / `drop:test:<path>` / `quit`）。

**小游戏的键盘**：两条路都要走通。① `keyPressEvent` 处理正常的键盘输入 —— 这里**只能**判 `Qt.Key_1/2/3`：Qt5 没有 `Qt.Key_NumPad1/2/3` 这几个枚举（且小键盘数字与主键盘数字共用同一个键码），写错会在 Qt 虚函数里抛 `AttributeError`，PyQt 随即 `qFatal()` 让**整个进程 abort**（0xC0000409），点个 Esc 桌宠就没了；② 另装一个应用级原生事件过滤器接管 `WM_KEYDOWN`：Windows 下若窗口不是焦点窗口（自动化直接 `PostMessageW` 就是这种情况），Qt 会丢掉键事件，只有原生过滤器能看到。两条路共用 `handle_action()`，命中后原生过滤器返回 `True` 吃掉消息，不会双触发。卡片还是一次性的——`main.open_rps` 里 `exec_()` 返回后 `deleteLater()`，不留隐藏窗口。

**离屏自检**：`QT_QPA_PLATFORM=offscreen python tools/smoke_features.py` —— 构造全套对象、跑一遍真实 `QDragEnterEvent`/`QDropEvent`、验证 `judge()` 9 种组合、`probe_peak()` 不抛、`MusicDetector.force()` 发信号、空跑数十帧 `_tick()`，最后打印 `ALL PASS`。测试会把 `APPDATA` 指到临时目录，不会碰真实配置。

## 常见问题

**按 Ctrl+Alt+B 没反应？**
先看托盘有没有「全局快捷键没抢到」的提示 —— 说明这组合键已被别的程序（常见于截图/录屏/输入法工具）占用。这不是本程序的问题，可以在那些软件里换键，或设置 → 交互里把「全局快捷键」关掉，用托盘图标唤出。

**拖文件到宠物身上没反应？**
必须拖到**宠物身体**上（窗口透明区不吃拖放事件）。也可以跳过鼠标直接验证：`python -c "…"` 或单实例通道发 `drop:test:D:\a.png`，看是否冒出「收到「a.png」…」的气泡。

**放着音乐它却不摇？**
1) 设置 → 交互 → 音乐感知是否开着；2) 系统音量是否静音（静音时峰值恒为 0）；3) 音量太小（低于 0.004）识别不到；4) 蓝牙耳机切换设备后，下一次 8 秒轮询会重新取默认设备。`music:status` 可以看当前峰值。

**等了半天 Buddy 也不自己溜达？**
1) 设置 → 交互 → 「空闲自动漫游」是否打开、触发时长是不是调大了；2) 「锁定位置」开着时按设计不漫游；3) 宠物隐藏 / 菜单弹窗打开期间不会启动；4) 有没有常驻工具在定时移动光标或模拟按键（`GetLastInputInfo` 会被刷新）；5) 发 `idle:on` 立刻预览，再看 `idle:status` 里的 `source / idle_sec / degraded` —— `degraded=true` 说明走的是光标近似判断，不是系统级空闲。

**点了左键没反应？**
先确认 WorkBuddy 的安装位置。设置 → 程序路径 → 浏览，选中 `WorkBuddy.exe`。默认会自动在注册表与常见目录（如 `D:\WorkBuddy`）里查找。

**宠物被别的窗口挡住了？**
右键 → 始终置顶。

**想换形象 / 加新特效？**
替换 `assets/ref/silhouette.png` 后运行 `python tools/make_frames.py` 重新生成眨眼帧；新特效在 `app/effects.py` 里继承 `BaseEffect`，并登记到 `EFFECTS` 与 `EFFECT_ORDER` 即可，菜单会自动出现。

**托盘图标不见了？**
Windows 会把新图标折叠进「^」里，拖出来固定即可。

**双击 bat 弹出一堆「不是内部或外部命令」/ 乱码？**
`.bat` 被存成了 UTF-8，而 cmd 按系统 ANSI（中文为 GBK）解析，中文注释会把命令行拆断。仓库里的 `启动桌面宠物.bat` 已改为纯 ASCII + CRLF，重新保存时请勿用 UTF-8 写中文注释；只想改路径的话直接用 `启动桌面宠物.vbs`。
