## 2. 产品目标与范围边界

**一句话目标**：让桌面宠物从「固定一只官方 Buddy」升级为「可从用户 WorkBuddy 已获得图鉴中选择形象并换肤」，且在云端不可用时仍能正常使用。

### 2.1 三个正交产品目标

| # | 目标 | 衡量口径 |
| --- | --- | --- |
| G1 连通 | 可靠拿到「已获得 Buddy 形象」清单，云端优先、离线可用 | 云端可用时清单与账号一致；断网 / 未配置时启动 3s 内完成降级且不阻塞 |
| G2 可选 | 用户能浏览、预览、选择并应用形象与皮肤 | 从打开面板到宠物完成切换 ≤ 2 次点击，且无需重启 |
| G3 不破坏 | 换肤不破坏存量视线跟随 / 眨眼 / 四边贴边 / 拖拽 / 特效 | 存量设置项 100% 沿用；素材不全时明确降级或拒绝，不崩溃 |

### 2.2 范围边界

| 本次做（In Scope） | 本次不做（Out of Scope） |

| 拉取时机、本地缓存、TTL、手动刷新、四级降级链 | 不做图鉴收集、抽卡、购买、养成、任务 |

## 5. 联动方式（云端接口适配器）

### 5.1 适配器职责边界

| 职责 | 说明 | 不做 |
| --- | --- | --- |
| 配置读取 | 读 `base_url`、鉴权占位、超时、TTL | 不硬编码任何真实地址 / 令牌 |
| 请求与鉴权 | 组装请求头、附带凭据、设置超时（建议连接 3s / 读取 5s） | 不实现登录换 token 流程 |
| 响应归一化 | 映射为内部 `Buddy{id, name, thumbnail, skins[]}` / `Skin{id, name, asset_ref, manifest}` | 不假设具体字段名（字段结构待确认，用适配层隔离） |
| 缓存读写 | 成功响应落本地快照（含拉取时间戳） | 不写 WorkBuddy 本地 DB |
| 降级判定 | 输出 `source` 枚举：`cloud / cache / builtin / default` + 原因码 | 不吞掉错误导致 UI 无感知 |
| 线程约束 | 网络请求在后台线程，主线程只接收结果信号 | 不阻塞 Qt 事件循环 / 不拖慢启动 |

### 5.2 鉴权占位

| 项 | 约定 |
| --- | --- |
| 存储 | `%APPDATA%/WorkBuddyPet/config.json` 可选字段（或独立凭据文件），**不入库、不进版本库** |
| 未配置行为 | 适配器短路返回 `NOT_CONFIGURED`，直接跳到降级链下一层；设置面板显示「尚未配置 WorkBuddy 云端连接」引导 |
| 安全性 | 界面回显脱敏；日志不打印完整凭据；配置错误给出可读原因而非堆栈 |

### 5.3 拉取频率

| 触发 | 行为 | 建议值 |
| --- | --- | --- |
| 应用启动 | 异步拉取一次；TTL 内命中缓存可跳过网络 | 启动时 |
| 手动刷新 | 用户点「刷新图鉴」强制忽略 TTL 走云端 | 随时 |
| 缓存 TTL | 超时后下次启动 / 打开面板时重拉 | **建议 24h**（待确认 Q7） |
| 失败重试 | 不在前台循环重试；退避交给下次触发 | 避免启动卡顿 |

### 5.4 失败降级链

| 层级 | 触发条件 | 数据来源 | UI 标注 | 可运行能力 |
| --- | --- | --- | --- | --- |
| L1 云端 | 已配置 + 网络正常 + 返回合法 | WorkBuddy 云端已获得形象列表 | 「云端 · 更新于 <时间>」 | 完整：全部已获得形象 + 皮肤 |
| L2 本地缓存 | 未配置 / 超时 / 5xx / 解析失败，且存在有效快照 | 上次成功拉取的本地快照（可过期） | 「离线缓存 · <时间>（可能不是最新）」 | 完整但可能陈旧 |
| L3 内置清单 | 无缓存或缓存损坏 | 随包内置 Buddy 清单（至少官方默认 Buddy） | 「内置清单」 | 仅内置形象与随包皮肤 |
| L4 默认 Buddy | 上述全部失败 / 素材加载异常 | `assets/frames/` 原始素材 | 「默认 Buddy」 | 与当前版本完全一致，保证不崩 |

> 约束：L1→L4 任一层的产出都必须是**同一内部数据结构**，UI 与 `assets.py` 不感知来源差异。

## 7. 皮肤切换逻辑与限制

### 7.1 形象与皮肤的关系

| 规则 | 说明 |
| --- | --- |
| 关系 | **1 个 Buddy : N 个皮肤**；皮肤列表随所选形象联动刷新，不跨形象复用 |
| 皮肤定义 | 皮肤 = 一套**完整贴图包 + manifest**，不是 CSS 主题；一个皮肤包对应一个素材目录（命名 / 尺寸规范见 7.2，格式待 Q5 确认） |
| 默认皮肤 | 每个 Buddy 必须有且仅有 1 个 `default` 皮肤；「恢复默认」即回到它 |
| 当前选择 | 以 `selected_buddy_id + selected_skin_id` 二元组持久化；形象变更时皮肤自动重置为该形象的 default |

### 7.2 素材完整性要求（对齐存量 `app/assets.py`）

| 素材 | 级别 | 缺失时行为 | 依据 |
| --- | --- | --- | --- |
| `buddy_0..5.png`（6 帧眨眼） | **硬依赖** | ❌ 判定「不可用」，禁用应用按钮并列出缺失帧 | `assets.py` 缺帧直接抛 `FileNotFoundError` |
| `buddy_base.png` | 视线依赖 | ⚠️ 降级：关闭该皮肤视线跟随（沿用 6 帧立绘），提示「该皮肤不支持视线跟随」 | `has_gaze()` 返回 False |
| `eye_l.png` + `eye_r.png` + `eyes.json`（三者齐备） | 视线依赖 | ⚠️ 同上；`eyes.json` 缺失或坐标字段非法同样降级 | `has_gaze()` / `eye_rect()` 依赖 `size` 与 `eyes.left/right` |
| `buddy_grip.png` | 可选 | ⚠️ 降级：贴边抓握改用通用姿态 / 不显示抓边立绘，提示「该皮肤无专属抓边姿态」 | `has_grip()` 已有降级路径 |
| `frames.json` / manifest | 建议 | ⚠️ 用默认值推断（frames=6、尺寸取首帧），标注「元数据缺失」 | 现有 `frames.json` 提供 `size` / `frames` |
| 尺寸一致性 | 强约束 | ❌ 6 帧 + base + grip 原始画布尺寸应一致（现为 `268×392`）；不一致判定不可用 | 缩放按统一 height 计算，尺寸不一会错位 |

### 7.3 切换流程

| 步骤 | 行为 |
| --- | --- |
| 1 | 选中皮肤 → 后台校验素材包（存在性、尺寸一致性、`eyes.json` 结构）→ 输出「可用 / 可降级 / 不可用」 |
| 2 | 不可用 → 置灰 + 列出缺失项 + 禁止应用 |
| 3 | 可用 / 可降级 → 点「应用」→ 原子切换素材目录 → 清空 `assets.py` 五级缩放缓存 → 重建资源 → 重绘窗口 |
| 4 | 失败（加载异常）→ **自动回滚**到切换前的 `buddy_id + skin_id`，并弹提示气泡 |
| 5 | 成功 → 写 `config.json` → 气泡「已切换为 <形象>·<皮肤>」 |

### 7.4 限制与兼容约束

| 限制项 | 结论 |
| --- | --- |
| 是否需要重启 | **不需要**，热切换；禁止用「重启生效」实现 |
| 是否保留位置 / 大小 | 保留：`size / opacity / pos / lock_pos / edge_cling / gaze_follow` 等设置全部沿用，不因换肤重置 |
| 与视线跟随兼容 | 素材齐备 → 保持 460px 触发 / 40px 死区 / 指数平滑不变；素材不齐 → 自动关闭该皮肤的视线跟随并在面板标注，**不改**用户全局 `gaze_follow` 设置 |
| 与眨眼兼容 | 必须 6 帧齐全且顺序为 `buddy_0..5`；待机眨眼节奏沿用现有逻辑 |
| 与四边贴边兼容 | grip 存在则沿用左右专用抓边立绘 / 上倒挂 / 下停靠；缺失走降级且不影响拖拽记位置 |
| 与特效兼容 | 10 个互动特效不改；仅作用于当前立绘，不因换肤失效 |
| 并发 | 切换过程中禁用重复点击；网络刷新与切换互不阻塞 |
| 版权 | 仅展示云端返回的「已获得」形象；原始图片落盘策略待 Q9 确认 |

## 8. 最终呈现效果与交互

### 8.1 UI 落点决策

| 方案 | 结论 |
| --- | --- |
| 设置面板新增「Buddy 图鉴」分组（**采用**） | 复用 `_section()` 暖色深灰卡片风格与现有滚动容器，改动最小、风格一致；图鉴是低频操作 |
| 独立图鉴悬浮面板（不采用） | 新增窗口生命周期 / 主题 / 托盘联动成本，本次不必要 |
| 右键菜单入口（**采用，辅助**） | 新增「切换 Buddy…」，点击打开设置面板并滚动定位到图鉴分组 |

### 8.2 「Buddy 图鉴」分组结构（自上而下）

| 区块 | 内容 |
| --- | --- |
| 状态条 | 数据来源标签（云端 / 离线缓存 / 内置清单 / 默认 Buddy）、更新时间、未配置引导文案；右侧「刷新图鉴」按钮 |
| 形象区 | 网格卡片：缩略图 + 名称 + 「已获得」标记；仅已获得项可选；不可用项置灰 |
| 皮肤区 | 随形象联动的皮肤列表：缩略图 + 名称 + 状态（默认 / 可用 / 可降级 / 不可用 + 缺失项说明） |
| 预览区 | 当前选中组合的实时预览（静态立绘 + 一次眨眼动画），标注是否支持视线跟随 / 抓边姿态 |
| 操作区 | 「应用」「取消」「恢复默认」三个按钮；有未提交变更时给出提示 |

### 8.3 交互流程

| # | 用户动作 | 系统响应 |
| --- | --- | --- |
| 1 | 右键 →「切换 Buddy…」或 设置 → 图鉴分组 | 打开面板；异步触发图鉴拉取（不阻塞界面） |
| 2 | 点「刷新图鉴」 | 强制走云端；成功更新列表与状态条；失败按降级链处理并提示 |
| 3 | 选中形象 | 皮肤区刷新为该形象的皮肤列表，预览更新，默认选中其 default 皮肤 |
| 4 | 选中皮肤 | 预览更新；显示素材校验结果与降级说明 |
| 5 | 点「应用」 | 热切换 + 持久化 + 成功气泡；失败自动回滚 + 原因气泡 |
| 6 | 点「取消」 | 放弃本次所有未应用的选择，预览回到当前生效组合 |
| 7 | 点「恢复默认」 | 一键回到官方默认 Buddy + 默认皮肤 + 原始 `assets/frames/`，并写回配置 |

### 8.4 切换时的提示气泡

| 场景 | 文案（示例） | 触发约束 |
| --- | --- | --- |
| 切换成功 | 已切换为「<形象名>」·「<皮肤名>」 | 受 `bubble_hint` 开关控制 |
| 降级切换 | 已切换为「<皮肤名>」，该皮肤不支持视线跟随 | 同上，且面板内保留常驻标注 |
| 刷新失败 | 云端暂不可用，正在使用离线缓存（<时间>） | 不弹模态错误框，不阻塞 |
| 未配置 | 尚未配置 WorkBuddy 云端连接，当前展示内置 Buddy | 状态条常驻 + 首次气泡 |
| 应用失败 | 切换失败，已恢复上一形象 | 回滚后提示 |

### 8.5 配置新增字段（建议，供架构师细化）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `selected_buddy_id` | str | `"default"` | 当前形象 |
| `selected_skin_id` | str | `"default"` | 当前皮肤 |
| `gallery_base_url` | str | `""` | 云端地址占位 |
| `gallery_auth_ref` | str | `""` | 凭据引用（不把明文 token 写进代码） |
| `gallery_cache_ttl_h` | int | `24` | 缓存 TTL |
| `gallery_last_sync` | str | `""` | 上次成功同步时间 |

> **兼容约束（必须遵守）**：`config.py::load()` 会过滤未知字段，因此上述字段**必须**加入 `Settings` dataclass；旧 `config.json` 缺字段时自动取默认值，无需迁移脚本。
